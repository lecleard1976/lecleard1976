The purpose of the CI/CD Pipeline is to move good changes as quickly and as automatically
as possible up to production and to reject bad changes as quickly and as automatically as possible.

## Overview

Continuous Integration/Delivery (CI/CD) is a development practice usually associated with Lean and Agile Principles of Software Development, that requires developers to check in updated code into a shared integration branch in their Source Code Management (SCM) repo on a regular basis, typically daily. On commit, these changes are automatically verified by an automated build, so that any errors can be identified quickly and corrected. The goal is to provide rapid feedback so that if a defect is introduced into the code base, it can be isolated and corrected as soon as possible. Tools are used to automate the testing and build a document trail.

Typically, continuous integration in practice amounts to the following:
- Use of a version control tool 
- Automated build process 
- Integrated automated unit testing 
- Automated alerts for failed builds or tests
